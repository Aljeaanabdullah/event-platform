# الحجوزات والتذاكر الإلكترونية والتحقق — Event Platform

> Phase 7. يعتمد بالكامل على دوال الحجز الآمنة من Phase 3 (لم يُعَد بناء منطق الحجز).

## مسار الحجز

| الخطوة                    | أين يحدث                                         | ملاحظات                                                                           |
| ------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------- |
| 1–3. اختيار النوع والكمية | `BookingPanel` (المتصفح)                         | الحد الأقصى = الأقل من `max_per_order` والمتاح. الإجمالي المعروض **تقديري فقط**.  |
| 4. التحقق من التوفر       | `reserve_tickets` (Postgres)                     | داخل نفس المعاملة بعد القفل                                                       |
| 5. الإجمالي بالفلس        | `reserve_tickets`                                | `price_fils × quantity`، رسوم الخدمة (0 حاليًا) والعمولة (5%) — على الخادم فقط    |
| 6–7. حجز مؤقت 15 دقيقة    | `orders.status = pending_payment` + `expires_at` | `quantity_reserved` تزيد؛ `release_expired_holds` (pg_cron كل دقيقة) تحرر المنتهي |
| 8. ملخص الحجز             | `/checkout/[orderId]`                            | من `orders`/`order_items` (لقطة السعر وقت الحجز) + عدّاد تنازلي                   |
| 9. المجانية تُؤكد فورًا   | `reserve_tickets` → `_finalize_order`            | تُصدر التذاكر ويُرسل إشعار؛ المستخدم يُحوَّل لصفحة الطلب                          |
| 10. المدفوعة → الدفع      | `/checkout/[orderId]`                            | Phase 8 (Sandbox)                                                                 |

- المتصفح يرسل **المعرّفات والكميات فقط** (`reserveSchema` يحذف أي حقل سعر).
- `cancel_pending_order`: المشتري يلغي حجزه المعلّق فتُحرَّر الكمية فورًا.
- حد 3 طلبات معلّقة لكل مستخدم (`max_pending_orders_per_user`) يمنع احتكار المخزون.

## منع البيع الزائد

1. `SELECT … FOR UPDATE` على صفوف أنواع التذاكر **بترتيب ثابت** (يمنع الـ deadlock).
2. فحص `quantity_total - quantity_sold - quantity_reserved` داخل نفس المعاملة.
3. القيد `ticket_types_capacity_check` (`sold + reserved <= total`) كخط دفاع أخير.

**اختبار تزامن حقيقي** — [`e2e/concurrency.spec.ts`](../e2e/concurrency.spec.ts): مستخدمان حقيقيان يرسلان 6 طلبات
متوازية (4 تذاكر لكل طلب) على نوع سعته 20 → يجب ألا يتجاوز المحجوز المتاح، وكل فشل سببه `SOLD_OUT` أو حد الطلبات المعلّقة،
ثم تُلغى الطلبات وتعود السعة كما كانت. ✅ نجح على قاعدة Postgres الفعلية.

> ما لم يُنفَّذ: اختبار الضغط الأكبر في [`scripts/concurrency-test.mjs`](../scripts/concurrency-test.mjs) (عشرات المستخدمين)
> يحتاج `SUPABASE_SECRET_KEY` لإنشاء مستخدمين — غير متوفر (انظر BLOCKERS).

## التذاكر الإلكترونية

- صفحة **تذاكري** `/account/tickets` (قادمة/سابقة) وتفاصيل التذكرة `/account/tickets/[id]`.
- كل تذكرة: رمز قصير مطبوع `T-XXXXXXXXXX` ورمز QR سري (256 بت، `qr_token`).
- الرمز السري لا يُقرأ إلا عبر `get_ticket_qr_token` التي تتحقق من الملكية؛ صورة QR (SVG) تُولَّد على خادمنا
  بمكتبة `qrcode` ولا تُرسل لأي خدمة خارجية. الصفحة `force-dynamic` (لا تخزين مؤقت).
- التذكرة المستخدمة أو الملغاة لا تعرض رمز QR.
- **PDF**: زر "طباعة / حفظ PDF" يستخدم طباعة المتصفح بتنسيق خاص — آمن لأن الرمز لا يغادر المتصفح.
- لا يمكن لمستخدم فتح تذكرة أو طلب غيره (RLS + تحقق المالك على الخادم → 404).

## التحقق عند الدخول (QR Check-in)

- `/organizer/check-in`: لأعضاء الجهة المعتمدة (owner/manager/scanner). اختيار الفعالية أولًا.
- مسح بالكاميرا (`jsQR` على إطارات الفيديو، يعمل على الجوال) أو إدخال الرمز المطبوع يدويًا.
- القرار في `check_in_ticket` (أو `check_in_ticket_code` للرمز المطبوع):

| النتيجة        | المعنى                                                             |
| -------------- | ------------------------------------------------------------------ |
| `ok`           | دخول مسموح — تحديث ذري `valid → checked_in` مرة واحدة فقط          |
| `already_used` | مُسحت سابقًا (مع وقت الدخول)                                       |
| `wrong_event`  | تذكرة لفعالية أخرى (لا تُستهلك)                                    |
| `void`         | تذكرة ملغاة                                                        |
| `invalid`      | غير موجودة **أو** الموظف ليس عضوًا في جهة الفعالية (لا نكشف الفرق) |
